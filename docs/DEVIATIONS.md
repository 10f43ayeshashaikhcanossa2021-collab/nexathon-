# INKLOOM AI — Architectural & Implementation Deviations

This document tracks all intentional deviations from the initial proposal, documenting the rationale, security implications, and production architecture decisions.

| Area | Proposal Specification | Implemented Architecture | Technical Rationale & Benefit |
| :--- | :--- | :--- | :--- |
| **Authentication & Session** | Client-side persona dropdown setting an arbitrary header (`X-Demo-User`). | Real bcrypt hashing (cost 12), signed HS256 JWTs stored in `sessionStorage`, with fresh DB user verification per request. | Eliminates critical security vulnerability where any client could impersonate administrators or reviewers. |
| **Domain Logic Enforcement** | Approval and workflow state logic managed inside React components. | Strict server-side Express state machine with role enforcement (`requireRole`) and audit logging. | Prevents client-side state tampering and ensures governance invariants cannot be bypassed via direct API calls. |
| **Anti-Self-Approval Guard** | Not enforced on backend; creators could switch personas and approve. | Server-side validation: if `created_by === req.auth.userId`, returns `403 Forbidden` (`SELF_APPROVAL_FORBIDDEN`). | Enforces fundamental governance integrity: authors (creators and admins alike) cannot certify their own submissions. |
| **AI Rule Grounding** | Prototype used hardcoded strings for Lumora Fitness (`F-12`, `50 gb`). | Dynamic, domain-agnostic retrieval and parsing engine reading directly from `approved_facts` and `brand_guidelines` DB rows. | Allows INKLOOM AI to govern any industry (verified via automated Northwind Bank financial test suite). |
| **LLM Output Validation** | LLM responses accepted directly into frontend UI. | 4-stage Validation Gate (`runValidationGate`) verifying verbatim excerpts, sent reference codes, taxonomy, and length bounds. | Neutralizes LLM hallucinations, fabricated reference citations, and prompt injection exploits. |
| **Evaluation Methodology** | Claimed 100% accuracy on an 8-case sample set. | 30-case multi-company benchmark split into `dev` (16) and `holdout` (14) with Precision, Recall, and F1 metrics. | Scientific rigor: true out-of-sample evaluation without misleading synthetic 100% claims. |
| **Document Text Extraction** | Listed `.pdf`, `.docx`, and `.txt` support. | `.docx` extracted via `mammoth`, `.txt` extracted natively; `.pdf` returns HTTP 415 with honest roadmap notice. | Prevents garbled multi-column PDF text extraction; avoids heavy native C++ binaries while maintaining high reliability. |
| **Social Publishing** | Implied direct live posting to LinkedIn, Meta, and X. | Realistic publishing sandbox validating platform character limits with explicit "simulated publish" audit records. | Real social integrations require 3P app verification and client secrets; simulation delivers complete workflow safely. |
| **Database Persistence** | Mixed local state and mock data. | Hosted Supabase PostgreSQL single source of truth across 15 relational tables with RLS and append-only triggers. | Production durability, transactional consistency, and complete historical auditability. |
